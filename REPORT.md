# Отчёт: крестики-нолики 3×3 и Minimax

## 1. Выбранная игра

Реализованы консольные крестики-нолики на Python: человек играет против ИИ.
Поле состоит из девяти клеток. Игроки по очереди ставят X и O; X начинает.
Три одинаковых символа по горизонтали, вертикали или диагонали означают победу.
Если поле заполнено и победителя нет, фиксируется ничья.
Человек может выбрать любую из двух сторон.

Состояние `GameState` хранит неизменяемый кортеж клеток, символ текущего игрока
и символ ИИ. `apply_move` возвращает новое состояние, поэтому перебор одной ветви
не изменяет другие ветви дерева.

## 2. Как работает Minimax

Для текущего состояния генерируются все допустимые ходы. Каждый ход создаёт
дочернюю позицию, для которой алгоритм рекурсивно рассматривает следующие ходы.
Поиск заканчивается только при победе, поражении или ничьей.

На уровнях хода ИИ выбирается **максимум** оценок дочерних позиций.
На уровнях хода человека выбирается **минимум**, поскольку предполагается,
что человек действует оптимально и старается ухудшить результат ИИ.
Результаты распространяются от листьев дерева к корню.

`choose_best_move` рассматривает все ходы ИИ и выбирает ход с максимальной
оценкой Minimax. После пробного хода ИИ следующий уровень является минимизирующим.
При равных оценках выбирается первая клетка по возрастанию номера.
Отдельного предпочтения самой быстрой победы нет.

При полном поиске оценка отражает исход против оптимального противника.
Поэтому ИИ не выбирает проигрышный ход, если может гарантировать ничью или победу.
В крестиках-ноликах из начальной позиции можно гарантировать ничью за любую сторону;
следовательно, такой ИИ не проигрывает человеку.

## 3. Оценочная функция

Оценки определяются с точки зрения ИИ независимо от его символа:

| Состояние | `evaluate(state)` |
|---|---:|
| Победа ИИ | +10 |
| Победа человека | −10 |
| Ничья | 0 |

Для незавершённой позиции функция также возвращает 0, однако Minimax не использует
этот ноль как окончательную оценку: он продолжает поиск до терминального состояния.
Глубина не прибавляется к оценке и не вычитается из неё, что сохраняет заданные
значения +10, −10 и 0.

## 4. Пример выбора хода

Человек играет X, ИИ — O. Сделаны ходы: X в клетку 1, O в клетку 5,
X в клетку 2. Теперь очередь ИИ:

| X | X | 3 |
|---|---|---|
| 4 | O | 6 |
| 7 | 8 | 9 |

Полный поиск даёт следующие оценки пробных ходов ИИ:

| Клетка | Оценка Minimax |
|---|---:|
| 3 | 0 |
| 4 | −10 |
| 6 | −10 |
| 7 | −10 |
| 8 | −10 |
| 9 | −10 |

ИИ выбирает клетку **3**: она блокирует верхнюю строку X и позволяет гарантировать
ничью. При любом другом ходе человек сразу занимает клетку 3 и выигрывает.
Максимальная оценка среди доступных ходов равна 0.

## 5. Глубина поиска

**Искусственного ограничения глубины нет.** Поиск выполняется до завершения партии.
Из пустого поля возможно не более девяти полуходов (ходов отдельных игроков),
а из текущей позиции — не более числа оставшихся свободных клеток.
Этого размера игры достаточно для полного перебора.

Параметр `depth` начинается с 1 после пробного хода ИИ и увеличивается на каждом
рекурсивном вызове. Он показывает глубину, но не останавливает поиск.
Для большой игры ограничение глубины и эвристическая оценка потребовались бы
для уменьшения времени расчёта. Здесь они не нужны: полный поиск обеспечивает
точную оценку исходов и гарантию отсутствия поражений.

## 6. Проверка

`test_game.py` проверяет выигрышные линии, ничью, оценки, допустимость ходов,
неизменность исходного состояния, пример из отчёта и консольный ввод.
Отдельная проверка перебирает все варианты ходов человека против реального
`choose_best_move` для ИИ за X и за O и проверяет, что ни одна такая партия
не заканчивается победой человека.
